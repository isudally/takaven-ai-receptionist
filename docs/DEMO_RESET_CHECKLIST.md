# Moka Motor Service Centre demo reset checklist

Use before each external browser/web-call demo. This is an internal checklist; it does not change the live technical runtime.

## Before the demo

- [ ] Browser/web-call mode is clearly identified as demo mode.
- [ ] The intended Receptionist agent and approved release version are open.
- [ ] Moka Motor Service Centre facts, hours, services and FAQ are loaded.
- [ ] Authentication is active; no secret is displayed or shared.
- [ ] Recording is off and the fictional demo retention setting is active.
- [ ] The callback destination is appropriate for the demo.
- [ ] Visible Sheet rows contain fictional demo data only.
- [ ] Prior test artefacts are cleared or separated without deleting required evidence.
- [ ] No customer names, contacts, recordings, private URLs or admin logs are visible.
- [ ] The presenter has the demo flow and capability boundaries available.

## During the demo

- [ ] Use fictional caller, vehicle and contact details only.
- [ ] Show an FAQ, a service enquiry, an appointment request and one correction.
- [ ] Use the callback branch only when it helps the prospect understand the boundary.
- [ ] Say request received/sent for confirmation; never say booked, confirmed, reserved or available.
- [ ] Do not expose n8n execution details, credentials or private administration screens.

## After the demo

- [ ] Confirm no customer data entered the demo records.
- [ ] Reset or archive demo rows according to the evidence-retention decision.
- [ ] Record commercial feedback separately from technical test evidence.
- [ ] Record a material defect for a planned release decision; do not start a micro-polish loop during the demo.
